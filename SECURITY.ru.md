## Как сообщить об уязвимости

**Не открывайте** публичный GitHub Issue по вопросам безопасности.

Сообщите приватно одним из способов:

1. [GitHub Security Advisories](https://github.com/sbezpalov/dev-workstation-maintenance/security/advisories/new) (предпочтительно)
2. Email мейнтейнеру из профиля репозитория / [Автор](README.md#автор)

Укажите:

- Затронутую версию (файл `VERSION` / `config/project.ini`)
- Описание и влияние
- Шаги воспроизведения (или минимальный PoC)
- Известна ли проблема публично

Подтверждение — в течение **7 дней**. Цель — как можно скорее выпустить исправление или рекомендации по смягчению.

## Что делает проект

Это **локальный Windows-инструментарий** обслуживания (`cmd` / PowerShell / `winget`). Он может:

- Устанавливать и обновлять ПО с правами администратора
- Читать API-ключи из `config/secrets.env` или CLI
- Писать переменные окружения в `HKCU\Environment`
- Удалять кэши и временные файлы на системном диске

### Секреты

- Храните ключи только в `config/secrets.env` (в gitignore) или передавайте через CLI на один запуск
- Шаблон — `secrets.env.example`; реальные значения не коммитьте
- В `logs/` не должно быть значений секретов; утечку считайте уязвимостью
- Ротируйте ключ, если он мог попасть в историю shell, скриншот или общий лог

### Повышенные права

- Перед применением смотрите `--dry-run` / `-DryRun`
- Machine-scoped `winget` и очистку всех профилей запускайте только когда готовы к UAC
- Регистрацию задачи (`register-scheduled-task.cmd`) выполняйте осознанно от администратора

## Вне области

- Уязвимости сторонних пакетов winget / npm / pip (репортить upstream)
- Локальная неправильная конфигурация (слабый аккаунт Windows, общий admin-сеанс, читаемый всеми `secrets.env`)
